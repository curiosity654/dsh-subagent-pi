# Project only shared Session semantics

The Session Projection records only Pi events that have exact official DSH meanings and explicitly omits unsupported Pi-only fields rather than inventing custom events or approximate transcript content. One Pi delegation is one DSH turn, each Pi model-and-tool cycle is one DSH step, final settlement is the sole authority for closing the turn, cumulative usage is replaced by its latest snapshot, and Pi settings including `defaultTools` remain native execution inputs rather than plugin policy.

A run-scoped single writer treats Pi's finalized user message as user authority, streaming updates as assistant and reasoning chunk authority, finalized assistant messages as assistant, tool-call, and usage authority, finalized tool-result messages as tool-result authority, and prompt settlement plus idle as terminal authority. Repeated message summaries on Pi turn or agent endings are consistency evidence only and are never appended again.

Mapped transcript content follows the official DSH Session persistence, retention, and spill policies without a Pi-specific redaction layer; content remains forbidden in Audit Diagnostics. Tool arguments preserve their streamed JSON text when available and otherwise use a stable serialization of the same parsed JSON value, while a value that cannot be represented as JSON is a Projection Failure rather than approximate transcript text.

The Pi SDK adapter is the sole normalization owner and emits one complete, de-duplicated internal run-event stream consumed by both result collection and Session Projection. Version 0.2 omits DSH `request/header` because the Pi seam does not expose the exact effective model request and tool schemas; partial request provenance is not persisted as if it were complete.

The normalizer is implemented locally against Pi 0.84.2 rather than copied from, or shared as a package with, the older rc.6 Agent Loop plugin. That implementation remains a reference for block conversion, step topology, and Session preparation, but its full AgentFactory, Inbox, continuation, direct callback-to-Session writes, and older terminal and tool authorities do not cross into the one-shot provider.

Four capability owners keep one control path: the Pi event normalizer owns native-event de-duplication, the Session projector owns valid DSH event topology, the Projection Agent owns DSH status and cancellation adaptation, and the provider alone coordinates admission, publication, result, and disposal. Normalization and Session append run synchronously in native callback order with no background event queue; the first append or invariant failure is captured as the run's Projection Failure, further projection stops, and no exception is thrown back into Pi.

Every invoked Pi tool is recorded in the Session Projection through paired official `tool/call` and `tool/result` events, including its name, call id, JSON arguments, supported result content, and error status. Result blocks without exact DSH semantics are omitted and counted in Audit Diagnostics; an otherwise unsupported-only result still appends a legal empty-content envelope so call pairing and outcome remain durable, while non-JSON arguments or broken pairing are structural Projection Failures. Audit Diagnostics contain only content-free projection phase, event category, counts, and failure location, because duplicating tool content would create a second sensitive and potentially divergent record.
