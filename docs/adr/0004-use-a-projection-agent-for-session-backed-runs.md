# Use a Projection Agent for Session-backed runs

DSH rc.7 derives official Subagent Catalog activity from a same-identity live DSH Agent, while Pi must remain the native Execution Authority. Version 0.2 therefore represents each published Pi Child Run with a minimal Projection Agent that owns DSH registry status and cancellation forwarding without running a DSH model loop or supplying execution policy; a run-scoped Session Projection Handle owns transcript and persistence, and the official DSH session-persistence capability is required so completed children remain durable instead of disappearing or being retained as unbounded live state.

The plugin fails activation when the official Session, Agent, persistence, or projection capabilities are absent and does not retain a Sessionless fallback. A child is published only after Pi native setup succeeds and before its first prompt: the provider prepares the same-identity Session and Projection Agent, appends the descriptor, announces both, and rolls every resource back without exposing an id if that boundary cannot complete.

The child header records its canonical Workspace, parent Session, subagent origin, and delegation depth, but omits `agentPreset` because the Projection Agent does not execute a DSH preset composition. The one-shot descriptor records only provider `pi` and the caller's label; each assistant message records its exact Pi provider and model through official message provenance, while run-resolved model and Thinking remain redacted Audit Diagnostics and actual tool use appears through standard Session events.

The child Session id is also the Projection Agent id and `SubagentRun.id`. DSH lifecycle run ids, background Job ids, and Pi-native in-memory session ids retain their separate owners and are never forced to match; Audit Diagnostics name `childSessionId` and `parentSessionId` explicitly instead of calling either one a lifecycle run id.

The dedicated Projection Agent exposes only the DSH behavior a read-only one-shot child actually has: running-to-idle status, cancellation forwarding with durable provenance, and a quiescence promise that follows Pi, projection, and persistence. It carries no DSH model options, does not drive its required Inbox, and rejects follow-up, steering, injection, and maintenance instead of silently accepting continuation work.

`SessionProjector.prepare()` returns one run-scoped `SessionProjectionHandle` that owns the prepared Session, Projection Agent, rollback-covered publication, event append, terminal finalization, explicit flush, and ordered detach. The provider coordinates this handle with the Pi session but does not reproduce raw Session and Agent lifecycle choreography or introduce a global Pi-child manager.

Version 0.2 keeps the existing Plugin Configuration unchanged and adds no Sessionless mode, persistence path, projection option, or migration for v1 runs that never had child Sessions. Its Compatibility Baseline is DSH rc.7, Pi packages 0.84.2, and Node 22.19 or newer; the package declares that engine requirement, while proving the actual `dsh` launcher resolves a supported Node remains a release gate rather than plugin configuration.
